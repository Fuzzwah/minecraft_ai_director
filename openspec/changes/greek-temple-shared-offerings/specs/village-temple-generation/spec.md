# Spec Delta

## ADDED Requirements

### Requirement: Use a Greek-inspired Keeper temple form
Each generated Keeper temple SHALL present a recognizable Greek-inspired civic
landmark rather than a compact utility room. The form SHALL include a visible
stone entrance, a front colonnade or equivalent column rhythm, a raised or
stepped base, a roofline or pediment silhouette, a traversable interior, and a
visible Keeper altar.

#### Scenario: Player approaches a normal village temple
- **WHEN** a player enters the village town center
- **THEN** the temple is visually distinguishable from ordinary houses and work sites
- **AND** its entrance, columns, roofline, and altar are visible without breaking blocks

#### Scenario: Abandoned village uses the temple root
- **WHEN** an abandoned town-center variant generates
- **THEN** it retains the Greek-inspired silhouette, usable entrance, and altar
- **AND** abandoned processors do not erase the temple's required structural identity

### Requirement: Preserve vanilla root compatibility while changing appearance
The Greek-inspired design SHALL fit each trusted Java 26.3 town-center root's
approved bounds, preserve all required road and village jigsaw connectors, and
remain valid in every supported root rotation. Its materials MAY vary by village
style but SHALL preserve a coherent temple identity.

#### Scenario: All supported styles and rotations are validated
- **WHEN** each normal and abandoned plains, desert, savanna, snowy, and taiga root is decoded and rotated
- **THEN** geometry remains within the trusted root bounds
- **AND** road connectors retain their states, metadata, and functional clearance
- **AND** the temple entrance, floor support, columns, roofline, and altar remain valid

### Requirement: Provide one integrated normal offering chest
Each supported temple root SHALL provide one empty normal chest at a trusted,
reachable temple location for both communal and private offerings. It SHALL NOT
provide an ender chest as part of the Keeper offering contract.

#### Scenario: Newly generated temple is inspected
- **WHEN** a supported town-center root generates in a fresh Java 26.3 world
- **THEN** exactly one normal offering chest is present in the temple root
- **AND** it is empty and has no generated loot table
- **AND** no ender chest is generated by the Keeper temple root

### Requirement: Remain Java 26.3 generation-compatible
The revised generation pack SHALL load before first generation on an unmodified
Java 26.3 server, preserve vanilla village placement and normal-versus-abandoned
selection, and SHALL NOT retrofit already generated village chunks.

#### Scenario: Pack is installed before fresh-world generation
- **WHEN** Java 26.3 generates supported villages with the revised pack enabled
- **THEN** each newly generated town center contains the Greek-inspired single-chest temple
- **AND** the pack reports no template, registry, or pack-format errors
- **AND** previously generated villages remain unchanged
